# ProofPatch

## Platform
web

Responsive desktop and mobile. The Next.js App Router, React and TypeScript frontend talks to a separate Hono API and queue worker. Shared live contracts and SQLite persistence remain separate from frontend presentation.

## Purpose and users
ProofPatch's current pilot turns Japanese PHP threat intelligence into a reviewable repair for the team's owned SakuraShop fixture. Supply Chain correlates the Japanese notice and vendor evidence with declared runtime inventory; Remediation proposes a constrained candidate; Development Security represents the worker's frozen checks and separate senior-review context. A deterministic controller governs promotion. A passing run publishes a draft PR for human review while deployment, configuration validation and incident assessment remain human work.

The pilot is a demonstrated workflow for one fictional Japanese merchant repository, not evidence of customer demand. Small TypeScript SaaS teams and broader Japanese development teams remain persona hypotheses; arbitrary repositories, continuous local watch and general repairs are future scope.

## Working behavior to preserve
**Agents → Live service is the default.** It shows service readiness, a connected target, source mode, actual run status and a real selectable/draggable/zoomable React Flow diagram. Live mode fetches Japanese and vendor sources; recorded-source mode discloses a snapshot while model calls, hosted checks and PR creation remain real. Offline, reconnecting, setup-required and failed states expose written feedback without prefilled model or test results.

Runs and events persist in the SQLite queue. The separate worker performs the workflow; the UI loads history, follows SSE snapshots/events with a bounded polling fallback, recovers active/latest results after reload, selects stored runs and exports recorded run JSON. JST event times, actual model IDs and usage, observed checks, runtime/policy logs, candidate SHA, real GitHub Actions results and returned draft PR links remain inspectable. English/Japanese controls switch recorded advisory titles, available agent summaries and senior-review summaries. Cancellation stops later stages; already in-flight external writes or CI may remain recorded.

The final hardened live demonstration produced [draft PR #3](https://github.com/Harsh5840/arigato-php-demo/pull/3) after actual Groq calls and hosted PHP verification. Its record contains 35 passed checks, including 15 business assertions. The exact run, CI, candidate and evidence identities are preserved in [IMPLEMENTATION-HANDOFF.md](../../docs/IMPLEMENTATION-HANDOFF.md). Draft allowed remains distinct from merge ready and finding closed, both false.

**Simulation is a separate retained mode.** It keeps deterministic dependency, local-change, PHP runtime and Composer compromise cases, stop/reset, role inspection, trace and `SIMULATED_DEMO` JSON export. Its inventory and execution results are fictional; real advisory links are research context. Leaving Simulation clears its run. Owner follow-up cases stay held even with five illustrative checks passed.

**Overview, Findings and Evidence retain the original synthetic workspace.** Queue filters and selection, evidence/diff/review dialog, failed-regression blocking, successful retry, local draft preview, export, reset, local per-finding persistence, evidence library and roadmap remain available. Those local demonstrations create no external PR. Their synthetic labels must stay visible alongside the actual live workflow.

On mobile, the Live first viewport names all three agents, their responsibilities and the baseline → repair → checks → human-review handoff. The longer graph has six numbered directional legend entries and distinct return lanes inside its default fit. Wider desktop routing keeps handoff labels between nodes. The final live review's **ship** disposition covers these two resolved material fixes only.

## Truth and evidence
Current implementation and [IMPLEMENTATION-HANDOFF.md](../../docs/IMPLEMENTATION-HANDOFF.md) are execution authority; the existing PRD and judging playbook remain product context. Live records must identify actual models, source mode and linked CI/PR evidence. Synthetic cases and local previews must remain labeled. Declaration matching is not exploit reproduction: the affected PHP image is never executed. Candidate CLI/business checks do not establish deployed web configuration, absence of compromise or complete security.

No merge, deployment or production tenant/authentication boundary is implemented. Pricing, savings, demand, defensibility, broader personas and the provisional build window remain hypotheses. No customer traction has been established.
